# KrKey Android - Project Context & History

This file serves as a memory and context document for AI assistants working on this project. It outlines the overall goal, strict architectural constraints, key domain knowledge, and a history of major decisions.

## Overall Goal
Create an extensible multi-script Brahmic IME for Android using Japanese-style flick gestures (up-direction only) and integrated Latin swipe typing. The UI uses a QMK-style layered architecture (inspired by a Sailfish OS QML prototype).

## Active Constraints & Architectural Mandates
- **Pure Commit Model:** Use `commitText` only (no `setComposingText` spans) for pecked text to bypass buggy third-party webview interactions (e.g., Perplexity AI text doubling). Replacements from the `CandidateView` MUST use `beginBatchEdit()` and `endBatchEdit()` to ensure atomic deletion and insertion without leaving duplicate partial words.
- **Pre-Deletion Space Query:** `needsPrecedingSpace(skipCount)` must be called BEFORE `beginBatchEdit`/`deleteSurroundingText` — some editors don't reflect deletions in `getTextBeforeCursor` until `endBatchEdit`. The `skipCount` parameter peeks behind the characters about to be deleted without actually deleting them first.
- **Multi-Touch Architecture:** Touch events are tracked using a dictionary of `PointerState` objects keyed by `pointerId`. No single-pointer state variables are allowed, ensuring fast two-thumb pecking doesn't drop keystrokes. Special keys (space, backspace, shift, symbol, globe, enter) are tracked the same way: their buttons are non-clickable and every touch reaches `handleGlobalTouch`. **Rollover:** a new pointer going down commits older character-key taps (and a non-dragging space) immediately, so output follows press order; a finger already moved up more than `FLICK_ROLLOVER_SLOP_DP` is left to finish its flick. Special keys act on lift only if the finger is still on the key (slide-off cancels, as with buttons); `gesturePath` and `gestureTimes` always stay the same length.
- **Exclusive Swipe Priority:** If a gesture (swipe) begins in Latin mode, it takes absolute priority. Existing concurrent touch-downs are marked as `canceled`, and new touch-downs are ignored until the swipe is complete to prevent accidental garbage characters during gesture typing.
- **QMK-Style Layers:** Layers are independent 2D lists. All character keys, including punctuation (comma/period), are pure `Pair(Base, Flick)` tuples defined directly in the layer grids in `KeyMap.kt`.
- **Four-Direction Keys:** the bottom-row punctuation keys (`COMMA_KEY`, `DANDA_KEY`, `PERIOD_KEY` in the Indic, Tamil and Latin grids) and, on the symbol layer, the digits, `#` and `/` are `FlickKey(base, up, left, right, down)`, with no down flick (too hard to hit on the bottom row); every other key stays a `Pair(base, up)`. In `buildGrid` their view tag is still `base to up` (so pair-only code keeps working), and the full key is on `FlickKeyView.flickKey`. The direction is the dominant axis past `FLICK_VERTICAL_THRESHOLD_DP` (`flickDirection`/`rawKeyOutput`), and an empty direction falls back to the base. These keys never start a Latin swipe, and rollover lets them finish a flick in any direction. `transliterateGrid` drops a direction that transliterates to the base. Test: `FlickKeyLayoutTest`.
- **Latin Layer Casing:** When dynamically applying casing in Latin mode (base=lower, flick=upper), the logic MUST verify `base.first().isLetter()`. Otherwise, punctuation tuples (e.g., `,` to `'`) are erroneously overwritten and appear blank.
- **Smart Auto-Spacing:** Use a "prepending" model `needsPrecedingSpace(skipCount)`. The keyboard checks text before the cursor (ignoring pending deletions via skipCount) and prepends a space to predicted words unless it's the start of a field, right after a newline, or right after sentence-ending punctuation (`.?!।॥`). Backspacing a swiped word deletes only the word and keeps the space before it (as AOSP/FUTO), so a retyped word does not stick to the previous one; a second backspace removes the space.
- **Automatic Spacing (FUTO-style `SpaceState`):** After a swipe: `PHANTOM` (the next letter/digit/opening bracket gets a leading space). After a picked candidate or sentence punctuation (`.,!?;:)]}।॥`): a real space is inserted, `ANTIPHANTOM` (a space tap is swallowed, punctuation moves in front of it, enter strips it; `;`/`:` never swap). Sentence punctuation also moves in front of a single space the user typed after a word ("word |" + "." → "word. |"), as FUTO's default mode does. Inserted (`ANTIPHANTOM`) spaces are skipped after digits and in URL/email/password/number/`TYPE_NULL` fields; the phantom space applies in any field (it mirrors the swipe's own prepended space). Neither applies when the text before the cursor looks like a URL/email; "e.g."/"i.e." are kept together. Cursor movement (`spaceStateAnchor`, with a 200ms settle window for late `onUpdateSelection` calls) or other input resets to `NONE`; shift/globe keep the state. Reimplemented from behaviour, not FUTO code (FUTO's licence is not GPL-compatible).
- **Spaces in Web Editors:** Firefox/WebView editors report a trailing space as a no-break space (U+00A0). Never compare with `' '` or use Java's `Character.isWhitespace` for spacing decisions; use `isSpace()` (any space separator except newline) or Kotlin's `Char.isWhitespace()`. Otherwise every swipe after a typed space gets a second space.
- **Backspace Key Events:** `deleteLastChar` sends a real `KEYCODE_DEL` key event in `TYPE_NULL` fields (remote input such as KDE Connect, terminals) and whenever there is no text before the cursor, as AOSP/FUTO do; `deleteSurroundingText` alone does nothing there. A selection is deleted with `commitText("")`.
- **Editors That Hide Their Text:** some editors (remote input such as KDE Connect, `TYPE_NULL` fields) never report the text before the cursor. `typedTail` remembers what we typed; `textBefore()` uses it when `editorHidesText` is set, from what the editor *declares*: `TYPE_NULL`, or `initialSelStart < 0` (no cursor position). Do not infer it from empty read-backs after a commit: asynchronous editors (Firefox/GeckoView) return empty right after commits while tracking the cursor fine, and the typed record then goes stale on cursor moves. That is what lets vowel signs follow consonants there. In such editors `deleteBefore()` deletes with `KEYCODE_DEL` key events. Always read, commit and delete through `textBefore`/`commit`/`deleteBefore`, never `InputConnection` directly, so the tail stays in sync.
- **Debug-Only Logging:** `DebugLog` and `SwipeLogger` have real implementations in `app/src/debug/kotlin` and no-op versions with the same API in `app/src/release/kotlin`, so release builds contain no logging code (`DebugLog.d { ... }` takes an inline lambda; the message is never built in release). `DebugLog` also appends to `files/debug_events.log` (rotated at 2 MB; `adb shell run-as com.akssri.krkey cat files/debug_events.log`). Anything that logs typed text must also check `learningAllowed`, so it never logs in password/incognito fields. Change both versions together when adding a method.
- **Password Fields:** No predictions, swipe typing or learning in password inputs; `IME_FLAG_NO_PERSONALIZED_LEARNING` fields disable learning only.
- **Numeric Keypad:** `TYPE_CLASS_NUMBER`/`DATETIME` fields get `NUMBER_GRID` and `TYPE_CLASS_PHONE` fields get `PHONE_GRID` (after FUTO's `number_basic`/`phone` layouts), via `InputMode.Numeric(phone, fromLatin)` chosen in `onStartInputView`. There is deliberately no key to leave the keypad; focusing a text field restores the full keyboard (`fromLatin`). Number grid: tap = ASCII digit (fields reject others), flick = the script's digit, date separators on flicks. Phone grid: FUTO's phone-symbols page is on digit flicks. Space is labelled ␣. There are no predictions (the candidate bar stays, for the clipboard chip), and all keys are given equal weight.
- **Candidate Bar Height:** the candidate bar stays visible on every layer (symbol, numeric keypad); only password fields hide it. Hiding it per layer changed the input view's height, so every layer switch resized the IME window, which is slow (window-manager calls plus an app relayout).
- **Clipboard Chip:** whenever the suggestion bar has no candidates (anywhere in the field, so it can be pasted mid-text; an empty-field-only version was tried and rejected), `CandidateView` shows a `📋` chip (icon only: the clip's text is never shown). Tapping it pastes the full text (with the phantom space after a swipe). It is hidden in password fields, and once pasted until the clipboard changes (`lastPastedClip`, reset by the clip-changed listener). The clip is cached in `currentClip` (read on field start and clip change), not re-read per edit. Read only `ClipData.Item.text`, never `coerceToText` (slow for URI clips).
- **One Symbol Layer:** `Symbol(fromLatin: Boolean)` is the only symbol mode; `fromLatin` picks the layer to return to and the numeral style. The second (math/Greek) symbol layer, `SymbolShifted` and shift lock were removed. The symbol layer has no shift key: its row-3 left key is `&`/`~`, and `<`/`>` are the up flicks of `[`/`]`. Digits flick up to ASCII and right to superscripts, `#` flicks right to the square-root sign, `/` flicks right to `|`, and `+`/`=` flick up to plus-minus and multiplication.
- **Landscape Overlay Insets:** In `onComputeInsets`, the touchable region width MUST use `decorView.width` (not `displayMetrics.widthPixels`) — the latter doesn't account for side navigation bars/cutouts, causing dead touch zones on the right side in landscape.
- **No Windows on the Key Path:** Key previews are views in `KeyPreviewLayer`, laid over the input view (the root is a `FrameLayout` of the keyboard and the layer), moved by translation and shown/hidden. Never use `PopupWindow` (or anything that adds, relayouts or removes a window) per key press: each window-manager call is a synchronous binder call to `system_server` that took 25–130 ms on a ZTE Libero Flip (~1 ms on an Xperia 1), making typing stall. Top-row previews are clamped to the top of the keyboard window, over the candidate bar.
- **Relabel Only What Changed:** `updateUI` relabels every key after every keystroke. Set key and button text with `setTextIfChanged`, never plain `setText`: `setText` re-shapes the text and relayouts the whole keyboard even when the text is unchanged.

## Key Domain Knowledge
- **Build:** Kotlin 2.1.0, AGP 8.7.3, compileSdk/targetSdk 36, minSdk 26, JVM target 17.
- **Dev Environment:** Nix flake (`nix develop`) provides JDK 21, Android SDK 36, platform-tools. `local.properties` is generated by the flake shellHook. aapt2 override is set via `GRADLE_OPTS`.
- **Build Command:** `./gradlew assembleDebug`
- **Install:** `./gradlew installDebug`
- **Linting & Formatting:** `./gradlew ktlintFormat`. An `.editorconfig` file is present to disable `max_line_length`, `property-naming`, and `no-wildcard-imports` so the declarative layout grids remain easily readable.
- **Swipe Decoder:** `WordPredictor.predict` aligns letters to the resampled swipe elastically, as a dynamic program over the dictionary trie. It searches as a beam (`BEAM` best prefixes per letter, ranked by cost plus `BEAM_ALPHA` × unexplained-swipe cost) with admissible subtree pruning; per-swipe key distances and letter-pair deviations are cached. Do not go back to exact DFS: it visits nearly the whole trie on long swipes. Predictors are cached across fields and cleared only on `dict_`/`script_` setting changes. They are built on a background thread (`PredictionManager.prepare`, started when a letter grid is laid out; only the key geometry is read on the UI thread), and predictions are empty until the build is ready: never build one on the UI thread. Swipes made meanwhile are held (`heldSwipes`) and decoded when it is ready, only if nothing else happened (no tap, flick or special key; cursor, layer and field unchanged). A failed build (exception or out of memory) leaves the mode without a predictor until `clearCache` or a new input view, instead of retrying on every keystroke. The weights are constants tuned in `tools/swipe-sim` (`elastic.py`'s `decode_beam` is the reference prototype). After changing either side, re-run `tools/swipe-sim/export_fixture.py > app/src/test/resources/swipe_parity.json` and `./gradlew testDebugUnitTest` (`WordPredictorParityTest`). Debug builds log swipes with `SwipeLogger` (`files/swipes.jsonl`, replay with `tools/swipe-sim/replay.py`).
- **Unicode Prediction:** `WordPredictor.kt` operates entirely on Unicode Code Points (`Int`) rather than UTF-16 `Char`s. This is strictly mandatory for supporting non-BMP Brahmi scripts via surrogate pairs.
- **Space-Bar Flick (ZWNJ):** In Indic layers, flicking up on the space bar types U+200C (zero-width non-joiner), which stops a conjunct after a virama (for foreign words). It goes through `onKeyInput`, so it is part of the word being typed. A drag needs mostly-sideways movement, a flick still counts after leaving the key, rollover leaves it to finish, and in Latin mode a flick is just a space. Keep U+200C written as an escape in source.
- **Spacebar Cursor & Akshara-Level Navigation:** Horizontal dragging on the spacebar calculates step increments (`SPACE_DRAG_STEP_DP` = 20f). In Latin mode, it sends synthetic `DPAD_LEFT` or `DPAD_RIGHT` `KeyEvent`s. In Indic mode, it navigates by whole orthographic syllables (aksharas / extended grapheme clusters) via `ic.setSelection`, preventing the cursor from landing in invisible sub-glyph positions (such as between consonant and virama or vowel sign).
- **Delayed Cluster Expansion (ZWNJ Decomposition):** Only the space-bar drag schedules it. When a drag leaves the cursor right after a conjunct, and it is still there 400 ms later (`CLUSTER_EXPANSION_DELAY_MS`, `expansionTargetSel`), `performClusterExpansion()` temporarily rewrites the cluster with ZWNJ after each joining virama so its parts are visible and editable. It must never be scheduled from `onUpdateSelection`, taps, app cursor moves or idle time: it is a real edit of the text. Inside it, the cursor always rests *before* a separating ZWNJ, never right after one (`snapBeforeZwnj` after drag steps and taps; moving right steps over the ZWNJ with the next syllable), so typed text joins the part on its left and the ZWNJ keeps the right part apart. It stays expanded while the user edits inside it: typing goes in as is (no word tracking or phantom space), a typed virama before a consonant gets a ZWNJ too, and backspace deletes one visible unit. `ActiveExpansion` records the offsets of the ZWNJs *we* inserted; `trackEdit` (called by `commit`/`deleteBefore` and the plain backspace) moves those offsets, the range and the tracked cursor `lastSelStart` with every edit. It collapses once (`collapseActiveExpansion`), when the cursor leaves it, text is selected, or on space, enter, shift, symbol, globe or field end; nothing re-expands it. Collapse reads the range around the cursor or selection (`readRange`), removes only our ZWNJs that are still ZWNJs (a user-typed one stays), and restores the cursor/selection shifted by the ZWNJs removed before it. If the editor returns less text than asked, the expansion is kept and the collapse retried (`collapsePending`, up to `MAX_COLLAPSE_RETRIES`) instead of leaving ZWNJs behind. Only one expansion exists at a time (a new one collapses the old first). Within `EXPANSION_SETTLE_MS` of our expansion edits or akshara cursor moves, `onUpdateSelection` keeps the tracked cursor (late updates report old positions) and `recheckExpansion` checks the editor's latest report once they settle. Cursor positions come from `cursorPos()` (tracked cursor), not from measuring the text (capped at 10k).
- **Syllable Backspace:** Outside an expansion, backspace deletes the whole syllable before the cursor (`backspaceLength`: `IndicClusterUtils.getTrailingAkshara` of the last 32 UTF-16 units, or of the pecked word; a conjunct with its vowel sign and marks, or one character with its combining marks in other text), and nothing after the cursor. To edit inside a syllable, drag onto it to expand it. Inside an active expansion, backspace deletes one visible unit, a half-consonant (C + virama + ZWNJ) at a time (`IndicClusterUtils.getTrailingDeletableLength`). Editors that hide their text or take raw keys (`TYPE_NULL`) still delete one code point per backspace (one key event).
- **Per-Layer Grids:** each layer's grid (keyed by its grid object in `ScriptData`) is built once by `buildGrid`, with its own `FlickKeyView`s and special-key buttons, and kept in `grids` (LRU, `MAX_GRIDS`). `showGrid` only swaps visibility and points `allKeys`, `specialKeyMap` and `shiftBtn`/`symBtn`/`spaceBtn` at the shown grid. So `updateUI` must call `showGrid` *before* labelling those buttons. A switch went from ~220 ms to ~50 ms on the ZTE. `onCreateInputView` clears the cache and resets `currentLayoutGrid` to `null`, so the new input view builds fresh grids. Nothing should hold on to key views across a switch (`PredictionManager` reads the current keys through a function).
- **Key Base (Conjuncts):** `updateBase` sets `currentBaseChar` from `ScriptData.keyBase(textBefore)`, the whole trailing consonant cluster (up to 4 consonants joined by virama; a nukta belongs to its consonant and any consonant may carry one, as in izzat; ZWNJ breaks it; `updateBase` reads 32 UTF-16 units, enough for 4 consonants each with a nukta in 2-unit scripts), or a trailing vowel. Vowel keys then show the whole conjunct with the vowel sign, while only the sign is committed (`getCleanOutput` strips the base). `formatKeyText` treats any base ending in a consonant as a consonant base. Key labels shrink to fit (22 down to 10 sp) via one `measureText` in `FlickKeyView.fitLabel` when the text, typeface or size changes. Not TextView auto-sizing: it searches sizes on every measure and made layer switches ~60 ms slower on the ZTE. Test: `KeyBaseTest`.
- **Script-Specific Labels:** The symbol mode button label uses Devanagari source text ("अल्") and `.toBrahmiScript(script)` for proper transliteration to any active script.
- **Language-Specific Hacks:**
  - **Dravidian Vowels:** In Kannada, Telugu, and Malayalam, the short "E/O" and long "E/O" tuples are explicitly swapped post-transliteration because short vowels are vastly more frequent in Dravidian languages.
  - **Devanagari Vowels:** In Devanagari, ए and ओ flick to ऐ and औ, and the rarely used short E/O (ऎ, flick ऒ) take the old ऐ/औ key on row 3 (`buildScriptData`). Other scripts still use the shared grid unchanged.
  - **Tamil Layout:** Tamil requires a heavily customized, non-Devanagari 1:1 grid (`TAMIL_INDIC_GRID`). It is ergonomically designed based on EMILLE corpus consonant frequencies to maximize left/right thumb alternation (vowels clustered left, high-freq consonants like க, த, ர clustered right).

## Major Artifact History & Milestones
- **Multi-Touch Migration:** Transitioned from single `x/y` tracking to `activePointers` map to solve fast-typing dropped key bugs. Added gesture exclusion to prevent pecking while swiping.
- **Cursor Control:** Built the spacebar swipe-to-move-cursor mechanism.
- **Auto-Space Overhaul:** Ripped out trailing space auto-inserts in favor of smart prepending spaces for candidate/gesture commits, fixing punctuation clash bugs. Later fixed pre-deletion query ordering — `needsPrecedingSpace(skipCount)` must be called before `beginBatchEdit` to avoid stale `getTextBeforeCursor` results.
- **Shift Toggle:** Converted standard shift into a dynamic script-switch toggle that reads the native `firstSyllable` of the active script to act as a UI indicator.
- **Declarative Punctuation:** Removed hardcoded `SpecialKey` enums for punctuation, moving them into the `KeyMap.kt` pure tuples.
- **Tamil Ergonomics:** Wrote a Python script to parse the csil-emille dataset for Tamil consonant frequencies, proving the efficacy of the right-heavy consonant clustering in `TAMIL_INDIC_GRID`.
- **Dead Code Removal:** Removed unused `TouchHandler`/`GestureDetector` pipeline, `viewPool` map, and `FlickKeyView.OnKeyListener` interface (~130 lines). Files kept in `gesture/` for reference only.
- **Code Simplification:** Merged `updateBase()` into `updateUI()` (eliminating 11 redundant call sites), extracted `resetInputState()` for the common 5-line reset pattern (4 call sites), simplified `onKeyInput` signature.
- **SDK 36 Migration:** Upgraded AGP 8.2.0→8.7.3, Kotlin 1.9.22→2.1.0, compileSdk/targetSdk 34→36, JVM 1.8→17. Fixed Nix flake for SDK 36 build-tools.
- **Nix Flake Setup:** Configured reproducible dev environment with `nix develop`, auto-generated `local.properties`, aapt2 override via `GRADLE_OPTS`.
- **Unified Symbol Modes:** Replaced separate `IndicSymbol`/`LatinSymbol` modes with `Symbol(fromLatin: Boolean)` to preserve context when switching.
- **Landscape Overlay Mode:** Added `onComputeInsets` override that sets `contentTopInsets = decorView.height` + `TOUCHABLE_INSETS_REGION` so the keyboard overlays the app instead of resizing it. `onEvaluateFullscreenMode() = false` suppresses the IME's built-in fullscreen extract editor. Whole-view `layout.alpha` controls transparency (0–100% via `keyboard_opacity_landscape` pref). Both overlay and opacity are gated on `landscape_overlay` boolean pref.
- **Split Layout Toggle:** `landscape_split` boolean pref gates the split gap computation. When split is off, `splitGapWeight = 0f` and no spacer is inserted. Gesture typing is disabled when `splitGapWeight > 0f` (the gap between halves would break gesture paths).
- **Settings Switches:** Added `SwitchCompat` toggles for "Split layout" and "Overlay mode" in the Landscape section of `SettingsActivity`. Each switch grays out its dependent slider (key width / opacity) when off via `alpha = 0.4f` + `isEnabled = false`.
